# easy-speedtest

[![CI](https://github.com/zuban/easy-test/actions/workflows/ci.yml/badge.svg)](https://github.com/zuban/easy-test/actions/workflows/ci.yml)

Консольная утилита на **TypeScript / Node.js**, которая измеряет скорость скачивания по заданному адресу.

Скрипт делает к URL **10 запросов строго последовательно** (следующий начинается только после того, как
тело предыдущего ответа получено полностью), затем печатает **среднее время запроса**, **общий объём
скачанных данных** и **скорость скачивания**.

Дополнительно: режим **`--watch`** — утилита следит за сменой сети (Wi-Fi → Ethernet, VPN и т.п.)
и перезапускает замер при каждой смене.

## Единицы измерения

| Величина | Единица | Определение |
|---|---|---|
| **Скорость** | **Мбит/с** (`Mbit/s`) | 1 Мбит = 1 000 000 бит — так считают провайдеры и speedtest-сервисы |
| Скорость (доп.) | МБ/с (`MB/s`) | 1 МБ = 1 000 000 байт; `МБ/с = Мбит/с ÷ 8` |
| Объём | МБ (`MB`) | 1 МБ = 1 000 000 байт (десятичные единицы СИ, не MiB) |
| Время | миллисекунды (`ms`) | |

## Быстрый старт

Нужен **Node.js 22+** (проверить: `node -v`).

```bash
git clone https://github.com/zuban/easy-test.git
cd easy-test
npm ci            # ставит dev-зависимости и сразу собирает TypeScript в dist/
node dist/cli.js https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

То же самое через npm-скрипт: `npm start -- <url>`.

Без клонирования (npm сам скачает и соберёт пакет из GitHub):

```bash
npx github:zuban/easy-test https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

## Параметры

```
speedtest <url> [options]

  -n, --count <n>          число последовательных запросов (по умолчанию 10)
  -t, --timeout <ms>       прервать запрос, если данных нет дольше <ms> (по умолчанию 30000)
  -w, --watch              не завершаться; повторять замер при каждой смене сети
      --poll-interval <ms> как часто проверять сетевые интерфейсы в режиме --watch (по умолчанию 2000)
  -h, --help               справка
```

Коды выхода: `0` — успех, `1` — сетевая ошибка или HTTP-статус не 2xx, `2` — неверные аргументы,
`130` — прервано по Ctrl+C.

## Как считается

- **Время запроса** — от отправки запроса до получения **последнего байта тела** (`performance.now()`).
  Редиректы (до 5) входят во время запроса — пользователь их тоже ждёт.
- **Объём** — сумма длин всех полученных чанков тела. Файл **не держится в памяти**: чанки считаются и сразу
  отбрасываются, так что можно мерить хоть на гигабайтных файлах.
- Отправляется `Accept-Encoding: identity`, а транспорт — `node:http(s)` без автоматической распаковки,
  поэтому считается ровно то, что пришло по сети.
- **Среднее время** = Σвремени / N.
- **Скорость** = Σбайт × 8 / Σвремени. Именно от сумм, а не среднее из N скоростей — так один быстрый
  запрос не перекашивает результат.
- Все запросы одной сессии идут через одно **keep-alive** соединение. Поэтому первый запрос обычно
  медленнее: он включает DNS + TCP + TLS-рукопожатие, остальные — нет. Это видно в построчном выводе.

## Режим `--watch` (смена сети)

```bash
node dist/cli.js https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg --watch
```

```
Watching network: en0 192.168.0.5
...замер...
Waiting for network changes… (Ctrl+C to exit)

Network changed: en0 192.168.0.5 → en0 192.168.0.5, utun6 10.8.1.2. Current measurement cancelled.
...новый замер...
```

- В Node.js нет события «сеть изменилась», поэтому утилита раз в `--poll-interval` опрашивает
  `os.networkInterfaces()` (дешёвый синхронный вызов) и сравнивает «снимки» — отсортированные списки
  внешних адресов (loopback и link-local IPv6 `fe80::` игнорируются).
- **Debounce 3 с**: при переключении Wi-Fi интерфейсы «мигают», поэтому изменение засчитывается,
  только если новое состояние продержалось 3 секунды. Кратковременный обрыв с возвратом в ту же сеть не
  вызывает перезамер.
- Если сеть сменилась **посреди замера**, он отменяется (`AbortController`): цифры, смешанные из двух
  сетей, бессмысленны. Пул соединений сессии уничтожается — сокеты старой сети не переиспользуются.
- Ошибка замера (например, сеть ещё не поднялась) не завершает процесс — утилита ждёт следующей смены.

## Архитектура

```
src/
├── cli.ts               точка входа: аргументы → сборка зависимостей → коды выхода, Ctrl+C
├── args.ts              разбор и валидация аргументов (node:util parseArgs)
├── session.ts           один замер: свой пул соединений + benchmark + вывод
├── benchmark.ts         N последовательных скачиваний; загрузчик внедряется извне
├── http/
│   ├── download.ts      потоковое скачивание: подсчёт байт, редиректы, таймаут простоя, отмена
│   └── agents.ts        keep-alive пул соединений на сессию
├── network/
│   ├── snapshot.ts      «снимок» сетевых интерфейсов (чистые функции)
│   └── watcher.ts       NetworkWatcher: опрос + debounce → событие 'change'
├── watch-mode.ts        оркестрация --watch: перезапуск/отмена замера при смене сети
├── stats.ts, format.ts  чистые функции: агрегаты и единицы измерения
└── reporter.ts          вывод в консоль (stdout/stderr внедряются)
```

Принципы: чистые функции отделены от ввода-вывода; всё, что трогает сеть, таймеры или ОС, передаётся
через параметры (загрузчик, источник сетевых интерфейсов, поток вывода) — поэтому каждый слой тестируется
изолированно, без моков модулей. В рантайме **нет ни одной npm-зависимости** — только стандартная
библиотека Node.js.

## Тесты и CI

```bash
npm run typecheck   # tsc --noEmit
npm test            # сборка + vitest: unit-тесты и e2e-прогон собранного CLI против локального HTTP-сервера
```

Тесты проверяют, в частности: что запросы действительно не перекрываются, точный подсчёт байт,
редиректы, 404, таймаут «зависшего» сервера, отмену, переиспользование одного keep-alive соединения,
debounce и «мигание» сети (на фейковых таймерах), перезапуск замера в `--watch`.

GitHub Actions:

- **[CI](.github/workflows/ci.yml)** — на каждый push/PR: typecheck + тесты на Node 22 / 24 / 26 (Ubuntu),
  а также macOS и Windows; затем smoke-прогон реального скачивания картинки из интернета, результат —
  в summary джобы.
- **[Speed test](.github/workflows/speedtest.yml)** — ручной запуск замера с раннера GitHub:
  *Actions → Speed test → Run workflow*, указать URL и число запросов, результат появится в summary.
